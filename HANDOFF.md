# Передача проекта «Второй пилот» на другой ПК

Дата: 2026-10-10. Хакатон, 20 часов.

## 1. Идея (итог обсуждения)
Умный видеорегистратор с экраном и динамиком — «второй пилот». Смотрит на дорогу и **голосом
предупреждает** водителя об опасностях. Главная фишка — анализ **поведения машины впереди**
(резкое сближение/торможение, виляние), а не только дистанции. Плюс пешеходы на пути и
автозапись ролика при опасной ситуации.

Как пришли к идее:
1. Начали с датасета BDD100K. Первое предложение — карта дефектов дорог (RoadPulse). Отказались.
2. Ваша идея: помощник водителя, говорящий об опасностях, например о поведении машины впереди.
3. Уточнили: это софт для регистратора с дисплеем и динамиками (сильнее, чем приложение на телефоне).
4. Формат: хакатон 20 часов → прототип на ноутбуке, видео с регистратора вместо железа.

Целевые клиенты: водители машин без ADAS, автопарки такси/доставки, страховые.
Конкуренты: Mobileye, Garmin, Samsara, Lytx, Nauto. Отличие: поведение соседних машин,
голос на местном языке, дешёвое железо.

## 2. Что сделано
Всё в git (локальный репозиторий, без GitHub). Подробности — `README.md`.

- Детекция: YOLO11n (COCO) через **ONNX Runtime**. PyTorch на исходном ПК блокировался
  Smart App Control, поэтому без него. Модели в `models/` (из HF `unity/inference-engine-yolo`).
- Свой трекер в стиле ByteTrack на numpy (`tracker.py`).
- Логика (`behavior.py`):
  - TTC по скорости роста рамки: `d ln(w)/dt = 1/TTC`, со сдвигом на полокна;
  - «на нашей траектории»: `|cx − 0.5| / w ≤ 0.7` (смещение в ширинах машины, не зависит от дистанции);
  - встречные: дистанция по ширине рамки / TTC > 12 м/с → игнор;
  - рамки сбоку (w/h > 1.9), у края кадра, на капоте — игнор;
  - пешеходы: смещение в метрах по росту (≤ 1.8 м), низ рамки ниже 0.7 кадра;
  - виляние: амплитуда > 0.15 ширины + ≥ 2 смены направления боковой скорости за 5 с;
  - подтверждение по времени (`CONFIRM_SEC`), а не по кадрам.
- Голос (`voice.py`): отдельный поток, приоритеты, анти-спам, выброс устаревших фраз,
  готовые `.wav` в `sounds/` (голос Windows Irina).
- Интерфейс (`ui.py`), автозапись событий (`recorder.py`), приложение (`main.py`):
  видео плавно 30 к/с, анализ в фоновом потоке на самом свежем кадре.
- Оценка (`evaluate.py`): события в CSV, `--snapshots` (снимки кадров в момент событий),
  `--labels` (поймано / заранее / ложные в минуту), `--tags` (день/ночь/погода из BDD100K), `--stride`.
- Тесты логики на синтетике: `test_behavior.py` (11/11).

### Результаты (ноутбук Intel Core 3 100U, без GPU; анализ ~6–10 раз/с)
| Ролик | Длина | Предупреждений | Комментарий |
|---|---|---|---|
| urban_cc0.ogv (Германия, CC0) | 2 мин | 0 | было 8.5/мин до настройки |
| krakow_cc_by.webm (Краков, CC BY 3.0) | 5 мин | 4 (0.8/мин) | 2 верных (пешеходы на зебре, 71.8 с и 214.4 с), 2 — встречный грузовик на повороте (45.7 с) |

**Не проверено на реальном видео:** срабатывание на резкое торможение машины впереди
(в этих роликах такого момента нет). Логика проверена только синтетическими тестами.

## 3. Установка на новом ПК
1. Распаковать архив `SoWeNeedAName_handoff.zip` (внутри — папка с историей git).
2. Установить Python 3.12 (python.org или `winget install Python.Python.3.12`).
3. В папке проекта:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   python test_behavior.py
   ```
   Должно быть `11/11 тестов пройдено`.
4. Тестовые видео в архив не входят (160 МБ). Скачать заново:
   ```bash
   mkdir data\videos
   curl -L -o data/videos/urban_cc0.ogv "https://upload.wikimedia.org/wikipedia/commons/e/ea/Dashcam_Recording_%28urban%29.ogv"
   curl -L -r 0-62914559 -o data/videos/krakow_cc_by.webm "https://upload.wikimedia.org/wikipedia/commons/transcoded/9/98/City_Driving_4K-_Krak%C3%B3w_Poland_2024.webm/City_Driving_4K-_Krak%C3%B3w_Poland_2024.webm.480p.vp9.webm"
   ```
5. Запуск демо:
   ```bash
   python main.py data/videos/krakow_cc_by.webm --start 66
   ```
6. Если на новом ПК есть NVIDIA GPU: `pip install onnxruntime-gpu` вместо `onnxruntime`
   и в `detector.py` добавить `"CUDAExecutionProvider"` первым в `providers`.
   PyTorch/ultralytics там тоже, скорее всего, заработает (если нет Smart App Control) —
   тогда можно дообучать модель на BDD100K.

## 5. Следующие шаги (по приоритету)
1. **DADA-2000 / BDD100K**: скачать 20–50 роликов в `data/videos/`, прогнать
   `python evaluate.py data/videos --snapshots snaps`, посмотреть снимки, подобрать пороги в `config.py`.
   Для DADA сделать `labels.csv` из их разметки момента аварии → метрики «поймано / за сколько секунд».
2. Найти и проверить момент **резкого торможения машины впереди** — ключевой для демо.
3. Записать фразы живым голосом в `sounds/*.wav` (имена: ttc, closing, weave, ped, brakelight, close).
4. Записать демо-видео со звуком (запасной вариант на случай падения на сцене).
5. Питч на 3 мин: крючок → решение → демо 60 с → как работает (TTC без дистанции,
   смещение в ширинах машины) → цифры («было 8 ложных/мин, стало 0.8») → рынок → финал.
   Статистику ДТП брать только из реальных источников (ВОЗ, МВД).

## 6. Известные ограничения
- Встречная машина на повороте может выглядеть как машина впереди → нужен гироскоп/разметка.
- «Своя полоса» — фиксированная трапеция + геометрия, не распознанная разметка.
- Виляние своей машины может дать «виляние впереди».
- Дистанция в метрах приблизительная (`CAMERA_HFOV_DEG`).
- Веса COCO, без дообучения.
